# H3 提示词写作指南（按官方分镜规范校正）

> 本指南分两层：**中文草稿层**用于和用户沟通、拆剧情与分镜；**官方结构层**是最终提交给 H3 的提示词格式。草稿可以用中文四段式整理，交付前必须转成官方三字段（Base）或六段（Full-Reference）结构，字段正文用英文，台词/歌词/画面文字保留原语言。
> 规则依据 MiniMax H3 官方两份原始文档：`skills/h3-prompt-writing/references/base-en.txt`（T2VA / I2VA / FL2VA / L2VA）与 `ref-en.txt`（全参考），来自 MiniMax-AI 官方仓库；摘要与差异对照见 `official-guide-notes.md`。规则快照日期：2026-11-20。

## 标准结构

### 官方提交结构

Base 任务（T2VA / I2VA / FL2VA / L2VA）三字段：

```text
integrated_multimodal_description: [Shot 1] … [Shot 2] At 00:SS.mmm, the camera cuts to …
overall_soundscape: [环境底噪、物理动作声、非语言人声]
non_diegetic_music: [乐器、速度、节奏型、动态变化，或 N/A]
```

Full-Reference 六段：`subject_definitions` → `summary` → `retention_analysis` → `detailed_description` → `overall_soundscape` → `non_diegetic_music`。

### 带图任务的对齐行（逐字照抄，第一行，后接空行）

```text
I2VA:  For the target video, at 0.00 seconds into the target video, <Picture 1> (from [Shot 1]) is fully referenced.
FL2VA: How the reference pictures align with the target video — Picture 1 (from Shot 1) aligns with the 0.00-second mark of the target video; Picture 2 (from Shot N) aligns with the S.SS-second mark of the target video.
L2VA:  How the reference pictures align with the target video — <Picture 1> (from [Shot N]) aligns with the S.SS-second mark of the target video.
```

`N` 为最后一镜序号，`S.SS` 为两位小数的实际时长。T2VA 没有对齐行，直接从三字段开始。完整模板见 `templates.md`。

### 中文草稿四段式（工作流内部使用）

```text
完整草稿 = 参考素材说明 + 核心创意 + 画面过程说明
```

当人物、风格、声音、文字或禁止项需要贯穿多个镜头时，加 `【整体要求补充】`，不要在每个镜头重复大段相同内容。草稿转官方结构时，四段内容分别落入对应字段：素材说明 → 对齐行/`subject_definitions`；核心创意 → `summary`/风格句；画面过程 → 主时间轴字段；整体要求 → 保留项与负面约束。

#### 参考素材说明

按上传顺序使用 `@图片1`、`@视频1`、`@音频1`。标签后先写用途，再写需要保持或排除的维度。

好：

```text
@图片1：人物参考，保持脸、短卷发和深绿色夹克，不参考背景文字。
@视频1：动作参考，只参考奔跑节奏和跨栏动作，不参考人物身份与场景。
```

差：

```text
参考图片和视频生成。
```

#### 核心创意

用一段话覆盖时长、画幅、主体、地点、事件、风格和特殊镜头规则。它负责锁定全片，不负责展开每个动作。

#### 画面过程说明

选择一种组织方式：

- 多镜头：按 `Shot N` 或秒数分段。
- 一镜到底：写成连续动作链，可用秒数标记阶段，但不要写切镜。
- 首尾帧：只写两帧之间的连续变化。
- 编辑：按时间段写修改发生的位置，并附全局保持项。

## 素材引用

- 每次直接使用某素材控制画面时，重复对应 `@标签`，不要只在开头笼统提一次。
- 多角色时给角色稳定名称，并说明谁对应哪张人物图。
- 参考图中存在无关文字、品牌或背景时，明确"不参考原图文字/Logo/背景"。
- 音频复用需要精确对白或歌词时，把文本写在提示词内，不依赖模型猜测。
- Full-Reference 标签体系：`<Subject N>` 可复用可见内容；`<Picture N>` 具体帧锚点；`<Video N>` 整段视频结构；`<Audio N>` 被复制或参考的音频信号。道具并入 Subject，不另设 Prop 标签。

## 镜头与时间（官方分镜规范）

### Shot 标记与时间戳

- `[Shot 1]` **不带时间戳**；后续每个镜头以 `[Shot N] At MM:SS.mmm` 起头，切点时间严格递增，且落在所选时长内。
- `[Shot 1]` 开头必须先给**风格词 + 初始构图**（`Cinematic` / `live-action` / `2D-animated` / `3D CG` / `claymation` / `watercolor` / `vintage film`）；关键帧任务从参考图推风格，T2VA 从用户文本选风格。
- 时间戳用单一切点时刻，不用时间段区间；`MM:SS.mmm` 保留三位毫秒。
- 切镜短语用自然英文：`the camera cuts to` / `the shot cuts to` / `the shot transitions to` / `the shot changes to` / `the shot switches to`。

### 切镜原则

- 一次切镜必须引入**新信息**：新主体、新空间、新状态、新视角或新时间。
- 仅距离拉近或角度微调，用运镜完成，不开新 Shot；两个镜头之间没有新信息，会得到两段模糊的半场景。
- 首尾帧任务默认一镜到底，聚焦两帧之间的连续变化，不主动加切镜。
- 普通切换写 `cut` 或"切镜到"；柔和叠化写 `fade`；节奏型内容写明由哪一拍触发硬切。
- J-cut：下一镜声音提前进入；L-cut：上一镜声音延续到下一镜。明确说话人从画外转为画内或反向变化。

### 每个 Shot 的最小信息

1. Shot 编号（首镜无时间戳，后续带递增切点时刻）。
2. 景别与主体。
3. 可见动作和表演节奏。
4. 相机位置、运动与结束构图。
5. 台词、环境音、动作音效或音乐变化。
6. 与前后镜头的切换方式。

### 拆镜原则

- 让单个镜头只承担一个主要叙事动作。
- 台词字数、动作复杂度与镜头秒数相匹配；5 秒最多 2 镜，10 秒最多 3–4 镜。
- 切镜时说明仍是之前哪个角色、切到什么景别、动作怎样接续。
- 运镜按官方三段式写：运动类型 + 幅度（`with small/large amplitude`）+ 速度（`at slow/fast speed`），写成句内自然英文；每镜至多 1–2 个；中等幅度与常速一般省略。官方词表与民间词映射见 `camera-vocab.md`。
- 环绕主体用 `Arc Shot`；不要写"环绕运镜"这类形容词。

### 一镜到底

使用同一空间中的连续因果链：主体动作引发相机追随、遮挡、转身、穿门或景深变化。可以分时间段，但全文不出现多个 Shot、硬切、叠化或"切镜到"。

## 台词与声音

H3 默认生成声音。对每段声音写清来源和时机：

- 对白：按发声顺序给稳定说话人 ID `(S1)`、`(S2)`，群言 `(S1,S2)`，跨镜不变；角色名、画内/画外、语言、台词原文、语气、口型同步写在 `<d>` 外；`<d>` 内只放语言标签和逐字台词，如 `<d>[Chinese] 醒醒，该出发了。</d>`。
- 画外音（旁白）：固定措辞 `says in an off-screen voiceover`，并写明画内角色嘴唇闭合。
- 台词跨切镜连续说完用 `<scenetrans>` 标注；视频结束台词被截断用 `<cutoff>`；不可辨认源词标 `[unclear]`，不猜测。
- 环境音：风、交通、人群、房间底噪、机械或自然环境。
- 动作音效：脚步、布料、碰撞、开门、按钮、武器或产品反馈音。
- 音乐：类型、速度、情绪、节拍触发点和是否复用参考音频；只写观众向配乐，画内收音机/乐器留在主时间轴。
- 音色：对应 `@音频N`，说明保持的是音色而非自动复用所有内容。

跨镜头对白示例：

```text
Shot 1：画外的母亲 (S1) says in an off-screen voiceover: <d>[Chinese] 醒醒，该出发了。</d>，声音在镜头结束前开始，画面中她嘴唇闭合。
Shot 2：At 00:03.000, the camera cuts to 母亲近景，她从画外转为画内，接着说：<d>[Chinese] 校车已经到了。</d>
```

不要背景音乐时在结尾写：

```text
non_diegetic_music: N/A
```

仍可保留环境音与动作音效。删除"配乐""BGM""音乐参考"等相反要求。

两个 `N/A` 不要用混（本轮校正点）：

| 字段 | 什么时候写 N/A |
|---|---|
| `non_diegetic_music: N/A` | 不要观众向配乐（人物听不到的那种）；环境音、动作音效照常写 |
| `overall_soundscape: N/A` | **仅当用户明确要求整段完全静默**；否则必须写环境音与物理声 |

`overall_soundscape` 用 1–4 句一段话写完，只写环境底噪、物理动作声与非语言人声，**不得复述台词、歌词或音乐**；`non_diegetic_music` 用 1–3 句，只写乐器、速度、节奏型与动态变化，不写"紧张""悲壮"这类抽象情绪词。

## 文字与图形

- 所有屏幕文字、字幕、标题、Logo、标语和按钮文案必须逐字写出，放进英文双引号，保留原语言、大小写和标点，不翻译不改写。
- 说明文字出现的媒介、位置、前中后景层级、动画方式、停留时长和是否被人物遮挡。
- 每镜头控制主要文字元素数量；优先短词和清晰层级。
- 需要保持参考图风格但不复刻原文字时，明确排除原图 Logo、标题与可识别文字。

## 负面约束

只写会显著改变结果的禁止项，并与正向画面一一对应。优先使用具体可观察的约束：

- "保持单一连续空间，不黑屏、不硬切"优于"不要奇怪转场"。
- "手绘线条始终为平面粉笔质感，不出现立体 CG 角色"优于"不要 AI 感"。
- "未提及的服装、背景构图和镜头节奏保持 @视频1 不变"适用于编辑任务。

不要塞入与当前任务无关的通用负面词库。

## 常见冲突

| 冲突 | 修复 |
| --- | --- |
| 上传了素材但没写用途 | 给每个素材补 `@标签：用途 + 保持维度` |
| 一镜到底却写多个 Shot | 改成同一空间的连续动作阶段 |
| 首尾帧模式写多次切镜 | 删除切镜，聚焦中间连续变化 |
| 为小构图变化开新 Shot | 距离/角度变化改用运镜；cut 只留给新信息 |
| 不要 BGM 又要求配乐 | 二选一，或明确音乐只在哪一段出现 |
| 要锁脸但无人物图 | 上传人物图，或把要求降为文字外观一致 |
| 3 秒镜头塞长台词 | 缩短台词或延长/合并镜头 |
| 提示词只有风格词 | 补主体外观、场景、动作和声音 |
| 编辑要求只有"改成更好" | 写清修改对象、目标状态和保持项 |
| 台词分给了错误角色 | 补稳定 `(Sx)` ID，身份语气放 `<d>` 外 |
| 旁白角色嘴唇在动 | 用 off-screen voiceover 措辞并注明嘴唇闭合 |
| 带图任务忘了对齐行 | 按任务补 I2VA / FL2VA / L2VA 官方对齐行，放第一行并空一行 |
| `N/A` 用混 | 配乐不要写 `non_diegetic_music: N/A`；整段静默才写 `overall_soundscape: N/A` |
| 字段正文夹中文描述 | 正文改英文，只有 `<d>` 内台词与屏显文字保原语言 |
| Ref2VA summary 没方括号 | 补 `[reference generation]` 这类任务类型前缀 |
| retention 标记自造 | 只用 fully_preserved / partially_preserved / attribute_transfer / weak_reference（音频另用 fully_copy / partially_copy / reference） |

## 自检表

- 结构是否完整且没有无意义重复？Base 三字段 / Ref2VA 六段顺序是否正确？
- 带图任务的对齐行是否逐字正确、在第一行、后接空行？`S.SS` 与实际时长一致？
- 每个素材是否有唯一编号、明确用途和保持维度？标签语义是否稳定？
- 时长按本工作流约定取 5–15 秒（标准版明确要求时可 4 秒；官方指南本身不规定片段时长），所有时间段是否在范围内、台词说得完？
- `[Shot 1]` 是否带风格词且无时间戳；后续切点是否严格递增、不越界？
- 每次切镜是否引入新信息；小构图变化是否误用切镜？
- 每个镜头能否在分配秒数内完成动作和台词？
- 一镜到底、首尾帧、切镜和转场要求是否互相兼容？
- 画面描述是否具体可见，而非抽象比喻？
- 对白、歌词和屏幕文字是否给出准确原文；台词是否带 `<d>` 与语言标签；`(Sx)` 是否跨镜稳定？
- 环境音、音效、音乐和音色要求是否明确且不矛盾；台词是否未混入 soundscape；`N/A` 是否用对？
- 编辑任务是否同时列出了修改项和保持项？
- 总字符数是否不超过 7000（平台输入上限，提交前核对一次）？
